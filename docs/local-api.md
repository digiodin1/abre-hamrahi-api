# Local panel API (1.7)

Account quota refreshes in a separate bounded worker every 30 seconds during work and every 60 seconds while idle. `state.connection` contains the provider's account-wide `used`, `total` (plan plus gift), and `checkedAt`; free space is `max(0, total - used)`. It includes retained versions and other account content, and is independent of the selected-folder volume ratio and bytes currently in transit. `quotaRefreshing`, `quotaError`, and `quotaStale` describe freshness. Failed reads preserve the last value, mark it stale, and back off for 60 seconds (300 after HTTP 429); values older than 90 seconds are also stale. Public model polling performs no provider requests. Background reads never refresh or restore authentication tokens.

This is a private desktop API bound to IPv4 loopback. It is not a server that the cloud provider can call. Do not forward or publish its port.

Read `GET /api/backup` for configuration, current stages, the last 30 run summaries, startup registration status, and the process CSRF token. Account tokens and passwords are never returned. `GET /api/status` is a small readiness response. Only the fixed UI assets are served; there is no arbitrary file download route.

Every action below is `POST /api/backup/<action>` with a JSON object, a same-origin `Origin`, and `X-Abr-Hamrahi-CSRF` from the current process. Restarting invalidates old CSRF tokens. Requests are limited to 64 KiB. Unknown actions and fields used as paths do not bypass the configured source checks.

| Action | Request / behavior |
| --- | --- |
| `config` | Save the full configuration. Includes `remoteRoot`, `folders`, `automatic`, `syncOnChange`, `startupEnabled`, `intervalMinutes`, `settleSeconds`, `maxFileMiB`, `verifyUploads`, and `exclude`. Each folder accepts `syncMode` (`instant` by default or `daily`) and `dailyTime` (24-hour `HH:MM`, default `02:00`). Folder names are derived from local paths, regardless of a supplied alias. |
| `folder-schedule` | `{ "job": "<configured ID>", "syncMode": "instant" or "daily", "dailyTime": "HH:MM" }`. Saves only that folder schedule while an upload is running. Path, enable flags, account and current pass are untouched. |
| `browse` | Open the Windows folder chooser; returns a selected path or cancellation. |
| `preview` | Start a local-only scan without contacting the provider. |
| `sync` | Start a full local-to-cloud mirror of active sources, including guarded native-trash reconciliation. |
| `audit` | Read-only full inventory and SHA-256 verification of all eligible local files against their exact cloud paths. Measures physical local totals, eligible totals, cloud totals and retained cloud extras. Writes local reports only; downloads content but does not upload, rename or delete cloud objects. |
| `folder-files` | `{ "job": "<configured folder ID>", "offset": 0 }`. Pages the latest full audit, 100 files at a time, with `localBytes`, nullable `cloudBytes`, status, error and cloud object ID. Missing cloud content is `null`, distinct from a zero-byte file. |
| `repair-audit` | Retry the currently allowed existing source files recorded as errors by the latest folder audits. Uses the normal safe synchronization path, including conflict checks and native replacement. Does not delete cloud-only files. Run `audit` again to confirm the complete result. |
| `connection` | Request an asynchronous account quota refresh, including while a backup is running. Returns `started: false` if another quota request is already active. |
| `test` | Perform a small upload/download verification. |
| `pause` / `resume` / `cancel` | Pause automation, resume pending work, or request cancellation after the current bounded operation. |
| `shutdown` | `{ "confirm": true }`. Acknowledges with `shuttingDown: true`, stops accepting new work, cancels the current run cooperatively, and exits after bounded cleanup. Settings, login, completed file records, and history remain on disk. |
| `items` | `{ "run": "<32 lowercase hexadecimal characters>", "offset": 0, "failedOnly": false }`. Returns up to 100 file records plus `total`. Page with offsets 0, 100, 200, etc. |
| `retry` | `{ "run": "<run ID>", "path": "<recorded failed local file>" }`. Starts a separate run containing only that file. The file must still exist in an enabled, non-excluded source without symlink/junction parents. |
| `reveal` | Same run/path shape. Selects the recorded file in Explorer. It does not execute files or serve their contents over HTTP. |

The `login`, `code`, `captcha`, and `logout` actions support the panel's account flow. Do not put credentials in query strings, command examples, issues, screenshots, or reports.

`shutdown` requires the same loopback, Host, Origin and CSRF checks as every other POST. Missing or non-boolean confirmation returns 400. An open folder chooser returns 409; close it and retry. Once exit is requested, subsequent POSTs return 503 while the listener remains available. The response acknowledges the request, not process termination: an in-flight network operation can still take time to finish. The launcher waits for its worker before releasing the private state lock. Reopening the browser does not restart the process; rerun the launcher. Closing the app does not disable an existing Windows sign-in startup entry. The settings button asks for confirmation and warns about unsaved edits.

The automatic master switch enables periodic reconciliation. `syncOnChange` adds debounced filesystem-triggered work. `startupEnabled` separately opts into the current user's Windows Run key; it is false by default. Failed registration leaves the configuration unchanged. If configuration persistence fails after registration, the previous registry value is restored.

Run items are persisted locally in SQLite and retained with the last 30 summaries. File states are `queued`, `processing`, `ok`, `unchanged`, `preview`, `trashed`, and `error`. The legacy summary `samples` field is limited to 100; use `items` for the full list. Files excluded by configuration are not sent or listed as eligible items. A run cut off by process exit is recovered at the next launch; unfinished file records become retryable errors. A file-only retry returns `partial: true` and never clears unrelated pending source changes.

New profiles default to `exclude: []` and `maxFileMiB: 0` (no application size cap). Existing configured exclusions survive upgrades. The application's own active state directory cannot be uploaded recursively. Symlinks and junctions are reported as errors. `state.transfer` exposes monotonic `sentBytes` within the run, `activeFiles` and average `bytesPerSecond`; it is separate from confirmed run results and the physical volume gauge. Part retries do not inflate sent bytes. File-level 403/500 failures remain retryable without aborting unrelated files; authentication and throttling still stop the batch and use bounded automatic backoff. A successful changed-path run does not schedule another immediate full scan; periodic reconciliation remains enabled.

`GET /api/backup` also returns `folderStats` keyed by configured folder ID. Each observation includes physical `localTotalBytes` (including excluded paths), eligible `localBytes`, observed `cloudBytes`, counts, `checkedAt`, `complete` and `stale`. `sizeUnreadable > 0` makes the physical local total a lower bound. Read-only audits retain cloud-only extras; a later successful full mirror sends eligible absent paths to native trash. Each observation records `assurance`: `sha256` requires downloaded content equality, while `size-and-identity` confirms indexed local content against the current remote identity and size. Size equality alone does not prove cryptographic content equality. `complete: true` is a point-in-time result, valid only with `stale: false`; restart, source notifications, config changes and further sync invalidate freshness. The latest audit inventory remains available independently of the 30-run history retention.

`syncMatch` uses only folder volume observations: `percent = 100 × min(cloudBytes, totalBytes) / max(cloudBytes, totalBytes)`, summed across enabled folders using physical `localTotalBytes` for the denominator, including excluded files. `eligibleBytes` and `excludedBytes` separately identify upload scope. It includes `cloudBytes`, `totalBytes`, `remainingBytes`, `extraBytes`, `stale`, `checkedAt`, `scope: "physical-folder-volume"` and `assurance: "volume-similarity"`. `matchedBytes` is a compatibility alias for `cloudBytes`. Counts, current run completion, hash checks and content-verification status do not enter this calculation. `complete` means volume equality only. Extra cloud volume lowers similarity; results stay in 0–100. Both zero totals yield 100; one zero total yields 0. Display rounds to two decimal places while never rounding unequal totals to 100. Missing observations return null. Stale observations retain their last measured ratio with a timestamp.

Full synchronization preloads validated recursive listings and caches directory membership for that operation; mirror writes use guarded native overwrite and trash. No custom history/manifests are created in mirror mode; an explicit legacy `syncBehavior: "versioned"` retains the old archive behavior. Up to eight files upload concurrently by default with independent snapshots and synchronized quota reservations and layout changes. Every upload requires a fresh get-object response matching its exact size, object ID, storage key, name and parent before indexing, even when optional SHA-256 readback is disabled. Independent HTTP requests run outside the session lock; refresh is synchronized. Multipart transfers stream at most four parts per file concurrently, maintain ordered completion receipts and never finalize after a failed part. Local queue insertion is batched; audit verification results and index proofs commit atomically in batches of at most 32. Uncommitted results remain queued and are conservatively rechecked after interruption. SQLite WAL retains full synchronous durability, and a database connection keeps the WAL alive through each operation.

Full audits use at most four download workers with separate staging files and serialized snapshot creation to respect free disk checks. Provider-recursive listings retain pagination and validate the parent graph; orphaned or duplicate IDs cannot produce a successful audit. A download may use the signed URL from its observed object listing; after a transient failure it fetches a fresh object URL. Every successful file requires the expected byte count and downloaded SHA-256. An entirely successful full audit can acknowledge its captured change generation; notifications arriving during it remain pending.

Audits always snapshot and hash eligible local files and read the current cloud inventory. A previous downloaded SHA-256 proof may be reused only for identical local SHA-256, size, cloud object ID, and the same opaque cloud revision (key, ETag, size, version and modification timestamp). ETags are never interpreted as content hashes. Receipts expire after the lesser of one hour and the configured reconciliation interval; missing revision metadata forces a fresh download. New uploads always receive fresh metadata verification; full downloaded SHA-256 verification is optional. `POST /api/backup/audit` with `{"deep":true}` forces every content download. `contentVerifiedAt` is the oldest actual download proof timestamp in a folder (Unix seconds), distinct from its current inventory `checkedAt`. This bounds repeated downloads while allowing active projects to converge quickly after edits.
