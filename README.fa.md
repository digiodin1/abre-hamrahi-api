# Abre Hamrahi API

برای ساخت میان‌بر و انتخاب پوشهٔ پروژه‌ها، [راهنمای اجرا و استثناها](docs/desktop-and-projects.md) را ببینید. میان‌بر، برنامهٔ بسته را اجرا می‌کند و اگر برنامه باز باشد همان پنل را نشان می‌دهد.

برای بستن پردازش پس‌زمینه، در «تنظیمات» دکمهٔ «خروج از برنامه» را بزنید و تأیید کنید. کار جاری متوقف می‌شود و برنامه پس از پایان درخواست در حال اجرا بسته می‌شود. تنظیمات ذخیره‌شده، ورود و فایل‌های موفق حفظ می‌شوند. بستن تب مرورگر پردازش را نمی‌بندد. خروج، گزینهٔ اجرای برنامه هنگام ورود به ویندوز را تغییر نمی‌دهد. مسیر محافظت‌شدهٔ خروج در [مستندات API محلی](docs/local-api.md) آمده است.

Abre Hamrahi API یک پنل محلی و رایگان برای پشتیبان‌گیری یک‌طرفه و نسخه‌دار از پوشه‌های ویندوز به ابرهمراهی است. پیش از ارسال، فایل‌ها snapshot و با SHA-256 بررسی می‌شوند؛ نسخه‌های قدیمی و حذف‌های محلی از ابر پاک نمی‌شوند.

نسخهٔ **۱.۳.۰** اجرای برنامه از میان‌بر، سینک فایل‌های تغییرکرده و بازیابی پایش پس از خطا را اضافه می‌کند؛ نام اصلی فایل‌ها و تاریخچهٔ جداگانه حفظ می‌شوند. برنامه پنج صفحهٔ حساب، پوشه‌ها، تنظیمات، پردازش‌ها و گزارشات دارد. وضعیت نسخهٔ برنامه به معنای رسمی‌بودن اتصال به سرویس نیست.

این پروژه اتصال رسمی نیست. در تاریخ ۴ نوامبر ۲۰۲۶، قرارداد پایدار و عمومی API یا WebDAV برای این گردش‌کار پیدا نشد؛ بنابراین پاسخ‌های ناشناخته عمداً باعث توقف امن عملیات می‌شوند و ممکن است تغییر سرویس به به‌روزرسانی آداپتر نیاز داشته باشد.

پنل فقط روی `127.0.0.1` گوش می‌دهد، اتصال غیرمحلی را رد می‌کند، مسیر آزاد برای خواندن فایل ندارد و برای نشانی‌های انتقال ابری تغییر DNS را بررسی می‌کند. سرویس ابرهمراهی نمی‌تواند از این API به رایانهٔ شما اتصال برگشتی بگیرد؛ برنامهٔ مخربی که از قبل با کاربر ویندوز شما اجرا شده باشد خارج از محدودهٔ حفاظت این ابزار است.

## نصب سریع ویندوز

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install .
abre-hamrahi-api
```

پنل روی `127.0.0.1` اجرا می‌شود و مرورگر فقط برای نمایش پنل است؛ زمان‌بندی تا وقتی پردازش برنامه روشن باشد ادامه دارد. اطلاعات خصوصی در `%LOCALAPPDATA%\AbrHamrahiAPI` نگه‌داری می‌شود و داخل پوشهٔ نصب یا مخزن قرار نمی‌گیرد.

## ترتیب استفاده

برای دکمهٔ انتخاب پوشه، مؤلفهٔ Tcl/Tk نصب Python لازم است؛ پنجره در پردازش مستقل باز می‌شود و سیاست اجرای PowerShell تغییر نمی‌کند. واردکردن دستی مسیر هم پشتیبانی می‌شود. نصب عادی، تغییر فایل‌ها را هر دو ثانیه بررسی می‌کند؛ برای رویدادهای native ویندوز می‌توانید `python -m pip install ".[native]"` را اجرا کنید. جزئیات تنظیمات و منابع طراحی در [راهنمای سینک خودکار](docs/automatic-sync.md) آمده است.

۱. وارد حساب شوید و در صورت نیاز ثبت‌نام یا پذیرش مقررات را در سایت رسمی کامل کنید.

۲. پوشه‌ها را اضافه و تنظیمات را ذخیره کنید. پوشهٔ state برنامه، ریشهٔ دیسک و symlink پذیرفته نمی‌شوند.

۳. پیش‌نمایش بدون ارسال را اجرا کنید، سپس بررسی ظرفیت و آزمون آپلود/بازیابی فایل کوچک را انجام دهید.

۴. پس از موفقیت آزمون، پشتیبان‌گیری را اجرا کنید. گزینهٔ «شروع سینک هنگام تغییر فایل» را فعال کنید تا پس از پایان نوشتن فایل، سینک خودکار با تأخیر کوتاه انجام شود. فاصلهٔ بررسی کامل برای ترمیم رویدادهای ازدست‌رفته باقی می‌ماند. سینک خودکار از پنل قابل توقف و ادامه است. بازیابی عمداً دستی است: فایل نسخهٔ دلخواه و manifest همان نوبت را از ابر دریافت کنید.

به‌صورت پیش‌فرض فایل‌های محیطی، کلیدهای خصوصی، credentialها، فایل‌های موقت و پوشه‌های وابستگی کنار گذاشته می‌شوند. این برنامه رمزنگاری سرتاسری ندارد؛ برای دادهٔ بسیار حساس، پیش از انتخاب پوشه آن را جداگانه رمزگذاری کنید.

## تنظیمات و گزارشات نسخهٔ ۱

- «همگام‌سازی خودکار» کلید اصلی بررسی دوره‌ای است. «با تغییر فایل‌ها هم شروع شود»، شروع سریع‌تر پس از تغییر را به آن اضافه می‌کند. برای دریافت تغییرات، کلید اصلی باید روشن باشد.
- «اجرای برنامه هنگام ورود به ویندوز» مستقل است: بعد از ذخیره، مسیر همین Python، تنظیمات و پورت را در کلید Run حساب فعلی ویندوز ثبت می‌کند. مرورگر باز نمی‌شود و دسترسی مدیر لازم نیست. پیش از جابه‌جایی یا حذف نصب، این گزینه را خاموش و ذخیره کنید.
- نام پیش‌فرض پوشهٔ اصلی، نام رایانه است. نام پوشه‌ها و فایل‌ها عیناً حفظ می‌شود؛ هش به نام فایل اضافه نمی‌شود. نامی که سرویس نپذیرد خطا دارد و خودکار عوض نمی‌شود. انتخاب هم‌زمان دو منبع هم‌نام پذیرفته نمی‌شود.
- در ساختار جدید، نام‌های قدیمیِ قابل‌تطبیق با فهرست محلی، پس از بررسی کامل هش در همان محل اصلاح می‌شوند و دادهٔ بدون تغییر دوباره آپلود نمی‌شود. اگر ساختار قدیمی و جدید هم‌زمان وجود داشته باشند، ادغام خودکار متوقف می‌شود. پردازش نسخهٔ قبلی باید پیش از استفاده از نسخهٔ جدید بسته شود و پوشهٔ تنظیمات و index حفظ شود.
- هنگام تغییر محتوا، نسخهٔ قبلی پس از بررسی هش به `_abre-backup-data/history` منتقل می‌شود و نسخهٔ جدید با نام اصلی ارسال می‌شود. درخواست بازنویسی یا حذف وجود ندارد. در صورت قطع ارسال ممکن است محل نسخهٔ فعلی تا تلاش مجدد خالی بماند، اما نسخهٔ قبلی در تاریخچه محفوظ است.
- فهرست بازیابی در `_abre-backup-data/manifests` ذخیره می‌شود. فایل و فهرستِ بدون تغییر دوباره آپلود نمی‌شوند. دو فایل با نام‌های متفاوت، مثل فایل اصلی و «Copy»، حتی با محتوای یکسان دو مسیر مستقل‌اند و خودکار حذف نمی‌شوند. جزئیات مهاجرت و بازیابی در [راهنمای نام‌ها و تاریخچه](docs/names-and-history.md) آمده است.
- در «پردازش‌ها»، مراحل و همهٔ فایل‌های واجد شرایط با صفحه‌بندی صدتایی دیده می‌شوند. کنار خطای فایل، «تلاش مجدد» فقط همان فایل را می‌فرستد و manifest جزئی می‌سازد؛ تغییرات دیگر همچنان در صف می‌مانند.
- «گزارشات» سی نوبت اخیر و خطاهای هر فایل را نگه می‌دارد. اجرای قطع‌شده هنگام شروع بعدی بازیابی می‌شود. لینک فایل، آن را در Explorer انتخاب می‌کند؛ فایل اجرایی خودکار اجرا نمی‌شود. فایل خارج از پوشه‌های فعال یا مستثناشده از این مسیر قابل بازکردن و ارسال نیست.
